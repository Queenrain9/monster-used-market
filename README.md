# 괴물 중고마켓 MVP v0.2.20.1 — Trade Record Layout Hotfix

이번 버전은 기능 추가가 아니라 **구조 목업과 실제 Godot 홈 화면의 비율/밀도/정보 위계를 맞추는 패스**입니다.

## 이번 패스에서 바뀐 홈

- 야시장 배경/장식 강조를 잠시 제거하고 중립적인 와이어프레임 톤으로 전환
- 검색창 → 상단 탭 → 한 줄 카테고리 → 시장 상태 → 매물 피드 → 하단 네비 순서로 재배치
- 카테고리 7개를 세로로 찌그러뜨리지 않고 한 줄로 배치
- 큰 시장 배너를 작은 상태 바 형태로 축소
- 매물 카드 높이를 약 96px로 줄이고 썸네일 / 이름 / 가격 / 지역·시간 / 태그 / 판매자를 분리
- 긴 텍스트는 카드 높이를 늘리지 않고 잘라서 피드 밀도 유지
- 특별 매물은 동일 카드 구조에서 테두리만 한 단계 강조
- 기존 검색/필터/조사/흥정/보유품/감정/재판매/저장 로직 유지

## 의도

현재 단계의 성공 기준은 “예쁜가”가 아니라:

1. 구조 목업과 화면 실루엣이 가까운가
2. 390×844 안에서 정보가 찌그러지지 않는가
3. 한눈에 매물 여러 개를 비교할 수 있는가
4. 이후 실제 아트를 교체해도 구조를 다시 뜯지 않아도 되는가

상세/감정소는 홈 구조를 실제 플레이로 확인한 뒤 같은 방식으로 다음 패스에서 맞춥니다.

## v0.2.12 — Item-Specific Investigation

두 번째 게임 디자인 개선 단계다.

이전에는 모든 아이템이 사실상 같은 `외형 / 각인 / 작동 / 출처 / 시세` 버튼을 공유했다. 이제 12개 아이템마다 플레이어에게 보이는 조사 지점이 다르다.

예:

- 달빛 속삭임 반지: `보석 결 / 안쪽 각인 / 마력 맥동 / 전 주인 / 반지 시세`
- 용의 이빨: `성장결 / 뿌리 단면 / 밀도·무게 / 채취 경로 / 용재료 시세`
- 저주받은 손거울: `은막 균열 / 뒷면 문양 / 반사 반응 / 소유 이력 / 저주유물 시세`
- 고블린 회중시계: `케이스 마모 / 무브먼트 각인 / 태엽 작동 / 수리 이력 / 시계 시세`
- 망자의 뼈피리: `골질 표면 / 마디 각인 / 음정·공명 / 연주자 출처 / 저주악기 시세`
- 심해 인어의 진주: `표면 결 / 천공 흔적 / 수분·마력 / 채취 해역 / 진주 시세`

### 구현 원칙

- 조사 기회 4회는 그대로 유지
- 숨겨진 진품/모조품/결함품, 상태, 단서 시스템은 그대로 유지
- 각 조사 행동은 기존 숨은 단서 슬롯과 연결되어 실제 정보를 공개
- 기존 저장 호환을 위해 내부 action ID `exterior / mark / function / origin / market`은 유지
- UI에는 내부 ID 대신 아이템별 `short_label`을 표시
- 조사 결과에는 어떤 행동을 했는지와 발견한 사실을 함께 표시

목표는 플레이어가 더 이상 “안 누른 공통 버튼이 뭐지?”가 아니라 **“이 물건은 어디를 봐야 하지?”**라고 생각하게 만드는 것이다.


## v0.2.13 — Content Scalability Pass

아이템을 늘릴 때마다 전용 조사 5개를 통째로 복사하던 구조를 제거했다.

새 콘텐츠 구조:

```
Item
├─ 기본 경제 데이터
├─ investigation_profile
├─ investigation_overrides (선택)
└─ unique_clues (선택)

Investigation Profile
├─ 조사 행동 5개
└─ profile clue pool

Common Clues
└─ 어떤 프로필에서도 fallback 가능
```

### 현재 재사용 조사 프로필

- ornament_magic
- organic_material
- enchanted_relic
- mechanical
- crafted_magic
- organic_instrument
- collectible
- arcane_container

여러 아이템이 같은 프로필을 공유한다. 예를 들어 `고블린 회중시계`와 `미믹의 황동열쇠`는 둘 다 `mechanical`을 상속하지만, 필요한 조사 행동만 개별 override한다.

### 단서 계층

1. 공용 `CLUES`
2. 프로필 전용 `PROFILE_CLUES`
3. 아이템 선택적 `unique_clues`

프로필 전용 단서가 일반적인 분위기를 만들고, 고유 단서는 특별한 아이템에서만 간헐적으로 등장한다.

### 확장성 검증

자동 테스트에서 `Content.ITEMS`에 등록되지 않은 가상의 새 기계 아이템을 생성하고:

- profile만으로 조사 5개 상속
- 조사 실행
- profile clue 사용
- 한 행동만 override
- 나머지 행동 자동 상속

까지 확인한다.

기존 세이브의 `exterior / mark / function / origin / market` 안정 ID는 그대로 유지한다.


## v0.2.14 — Information Economy Rebalance

고정 정보 비용을 제거했다.

이전:

- 재질 검사 120G
- 마력 검사 160G
- 내부 구조 200G
- 전문 감정 300G

문제는 1,500G 물건과 20,000~30,000G 물건에서 같은 비용을 내기 때문에 고가 물건에서는 전문 감정이 사실상 공짜 보험이 된다는 점이었다.

이제 비용은 **플레이어가 실제로 지불한 매입가**를 기준으로 계산한다.

| 정보 | 기준 | 최소 | 최대 |
| --- | ---: | ---: | ---: |
| 재질 검사 | 매입가 2% | 100G | 700G |
| 마력/반응 검사 | 매입가 3% | 150G | 900G |
| 내부 구조 | 매입가 4% | 200G | 1,200G |
| 전문 감정 | 매입가 7.5% | 300G | 2,500G |

50G 단위로 반올림한다.

예:

- 1,500G 매입 → 100 / 150 / 200 / 전문 감정 300G
- 20,000G 매입 → 400 / 600 / 800 / 전문 감정 1,500G
- 30,000G 매입 → 600 / 900 / 1,200 / 전문 감정 2,250G

### 설계 원칙

- 비용은 `purchase_price`만 사용
- 실제 가치, 진품/모조품, 희귀도 등 숨은 정보는 비용 계산에 사용하지 않음
- 따라서 감정 비용만 보고 대박/함정을 역추론할 수 없음
- 추가 검사는 저렴한 부분 정보
- 전문 감정은 비싼 완전 정보
- 추가 검사 뒤 전문 감정을 하면 앞선 검사비가 환급되거나 할인되지 않음
  - 처음부터 완전 정보가 필요한지
  - 싼 부분 정보만 사고 멈출지
  - 아무 정보 없이 판매할지
  를 거래마다 결정해야 함


## v0.2.15 — Monster Local Marketplace Fantasy

이번 패스는 새 시스템을 늘리는 대신 기존 매입 루프의 **감정적 표면**을 바꾼다.

목표:

> 시스템이 생성한 아이템을 평가한다
>
> ↓
>
> 어둠마을 근처의 괴물이 올린 수상한 중고 매물을 보고, 직접 말을 섞고, 가격을 제안해 받아온다

### 홈 피드

- 시스템 단서 대신 판매자가 직접 쓴 듯한 매물 사연을 노출
- `보기`보다 `글 보기`에 가까운 표현
- `가격 협의` → `가격 제안`
- `특별 매물` → `동네 인기 매물`
- 모든 판매자가 서로 다른 동네에서 매물을 올림

### 매물 상세

- 물건마다 3종의 seller-written story pool 추가
- 판매글 본문과 판매자의 주장 분리 없이 실제 게시글처럼 이어서 표시
- 동네 / 올린 시각 / 직거래 장소 / 가격 제안 가능 여부 표시
- 판매자 초상, 프로필, 주 활동 동네 표시
- 판매자 성향의 정답 라벨은 계속 숨기고 행동 단서만 노출

### 괴물 판매자 로컬 정보

8명의 판매자 각각에:

- neighborhood
- meetup
- profile

을 추가했다.

예:

- 유령 모르나 → 묘지길 / 묘지길 가로등 아래
- 고철상 그리즐 → 고철부두 / 3번 크레인 앞
- 해골 악사 토토 → 뼈다리 광장 / 작은 무대 옆
- 까마귀 루크 → 종탑 뒤편 / 우편함 앞

### 가격 제안 화면

기존 협상 수학은 그대로 유지한다.

표면 표현만:

- `가격 협상` → `가격 제안`
- `판매자 요구가` → `판매자가 올린 가격`
- `제안` → `제안 보내기`
- `구매` → `바로 거래`
- 판매자 동네와 실제 직거래 장소 유지
- 첫 반응을 시스템 문구가 아니라 판매자 답장처럼 표시

### 직거래 완료

구매 후에는 단순히 인벤토리에 들어갔다고 말하지 않고 실제 meetup 장소에서 직거래를 마쳤다는 맥락으로 보유품에 들어온다.

### 기존 저장 호환

예전 저장 파일에는 `listing_story / neighborhood / meetup / profile`이 없다.

렌더링 시 item_id / seller_id 기준으로 최신 공개 콘텐츠를 찾아 자동 보완하므로 기존 저장도 새 중고거래 표현을 사용한다.


## v0.2.16 — Conversation & Inspection Fantasy

괴물 중고거래 판타지를 한 단계 더 밀어붙였다.

### 홈 카드

홈 카드의 메타 정보에 판매자 이름을 직접 노출한다.

`판매자 · 동네 · 올린 지`

형태로 보여서 아이템 목록이 아니라 **누군가 실제로 올린 매물**처럼 읽히게 한다.

### 상세의 조사 행동

내부 조사 시스템은 그대로 유지하지만 플레이어 문구를 실제 거래 행동으로 번역한다.

예:

- `성장결` → `성장결 사진 보기`
- `뿌리 단면` → `뿌리 단면 사진 요청`
- `밀도·무게` → `밀도·무게 확인`
- `채취 경로` → `어디서 얻었는지 묻기`
- `재료 시세` → `비슷한 매물 찾아보기`

### 상호작용 기록

조사를 실행하면 상태바 한 줄로 끝나지 않는다.

상세 화면 안에 마지막 상호작용이 남는다.

- 사진 요청: `나 → 판매자 → 사진에서 확인`
- 출처 질문: `나 → 판매자 답장 → 대화하며 확인`
- 직접 확인: `직거래 전 확인 → 관찰 결과`
- 시세 조사: `비슷한 매물 검색 → 비교 결과`

기존 `discovered_clues`는 그대로 유지되므로 게임 로직과 저장 구조를 깨지 않는다.

### 판매자 성격 표현

구매 전에는 `급한 판매자`, `전문가` 같은 정답 라벨을 계속 숨긴다.

대신:

- 방금 답장함
- 오늘 거래 선호
- 실제 판매자 메시지

를 보여주어 플레이어가 성향을 직접 추론한다.

### 거래 정보 압축

기존의 DB형 상세표를 줄이고 핵심만 남긴다.

- 직거래 장소
- 올린 지 얼마나 됐는지
- 가격 제안 가능 여부

카테고리/확인 상태 같은 시스템 정보보다 로컬 거래 맥락을 먼저 보게 한다.

### 호환성

`last_inquiry`는 매물 Dictionary에 선택적으로 저장된다.

예전 세이브에는 이 필드가 없어도 문제 없고, 새 상호작용을 한 뒤부터 자동으로 저장된다.


## v0.2.17 — Conversation Coherence & Purchase Handoff

v0.2.16 실제 플레이 캡처에서 드러난 다섯 가지 문제를 정리한 패스다.

### 1. 질문과 단서의 의미 일치

기존에는 조사 action이 `investigation_clues` 배열의 위치만 사용해:

- 출처 질문 → 외관 마감
- 사진 요청 → 판매자 행동

처럼 질문과 답이 어긋날 수 있었다.

이제 구매 전 조사는 semantic channel을 사용한다.

- `exterior` → 표면/외관 단서
- `mark` → 제작 표식/각인 단서
- `function` → 작동/마력 반응 단서
- `origin` → 출처/수리/소유 이력 단서
- `market` → 동종품 시세

모든 단서에는 내부 signal이 남지만 구매 전 UI에서 긍정/부정/애매 라벨은 계속 숨긴다.

일부 조사는 의도적으로 `neutral` 결과가 나오므로 모든 질문이 정답 버튼이 되지는 않는다.

### 2. 홈 카드 판매자 가독성

홈 카드의 본문 폭을 넓히고 카드 높이를 조금 늘렸다.

메타 정보는:

`판매자 · 동네 · 올린 지`

를 본문에 직접 표시한다.

오른쪽에는 판매자 초상과 글 보기만 남겨 물건 목록보다 **누가 올린 거래글인지**가 먼저 읽히도록 했다.

### 3. 가격 계획 CTA 분리

`내 가격 정하기`는 더 이상 조사 행동 5개와 같은 Grid 안에 있지 않다.

조사 5개 아래에 별도 full-width CTA:

`이 물건, 얼마까지 낼지 정하기`

로 분리했다.

### 4. 판매자 가격 문구

첫 제안 전:
- `판매자가 올린 가격`

카운터/거절 이후:
- `현재 판매자 가격`

으로 구분한다.

따라서 원래 등록가와 협상 중 현재가를 혼동하지 않는다.

### 5. 직거래 → 보유품 handoff

구매 완료 후 보유품 화면에 직거래 완료 카드가 나타난다.

- 누구에게 샀는지
- 어디에서 받아왔는지
- 실제 구매 가격
- 현재 감정 상태

를 먼저 보여준다.

보유품이 하나뿐일 때는 큰 ItemList를 숨겨 빈 디버그 패널처럼 보이지 않게 하고, 물건 이미지와 거래 결과를 바로 보여준다.

기존 저장에는 `purchase_context`가 없어도 listing의 seller/meetup 데이터로 fallback한다.

## v0.2.18 — Chat-first Inquiry

실제 플레이에서 `더 알아보기`가 여전히 “버튼을 눌러 정보 패널을 여는 메뉴”처럼 느껴지는 문제를 해결한다.

### 구조 변경

이전:

```
더 알아보기
[사진 보기] [사진 요청] [반응 확인]
[출처 묻기] [시세 보기]

→ 마지막 결과 패널
```

현재:

```
판매자와 대화
┌ 판매자 프로필 / 최근 접속
│ 판매자: 첫 메시지
│
│            나: 질문
│ 판매자: 답장
│ 거래 메모: 관찰 결과
│
│ 무엇을 보낼까요?
│ [대화 선택지] [대화 선택지]
└ [직접 검색]
```

질문 선택지는 이제 별도 조사 메뉴가 아니라 **채팅창 안의 답장 선택지**다.

### 누적 대화

매물은 선택적으로 `chat_history`를 가진다.

질문할 때마다 이전 대화가 사라지지 않고 계속 누적된다.

- buyer
- seller
- note

세 종류의 메시지를 저장한다.

상세를 나갔다 다시 들어와도 같은 대화가 남는다.

### 상호작용

- 외관 → 사진을 더 요청하는 대화
- 제작 표식 → 해당 부위의 근접 사진 요청
- 기능 → 직접 확인해도 되는지 묻는 대화
- 출처 → 판매자에게 직접 질문
- 시세 → 판매자 대화가 아니라 플레이어의 외부 검색 메모

기존 semantic clue channel과 조사 기회 4회는 그대로 사용한다.

### 정보 계층

`거래 메모`는 대화에서 얻은 사실을 다시 볼 수 있는 보조 영역일 뿐이다.

플레이어의 1차 경험은 이제:

> 버튼 → 정보

가 아니라:

> 질문 선택 → 나의 메시지 → 괴물의 답장 → 내가 얻은 관찰

순서다.

기존 `last_inquiry` 필드는 이전 저장 호환을 위해 남기지만 새 UI는 사용하지 않는다.

- 하나의 대화 스크롤
- 판매자의 첫 메시지
- 누적된 buyer/seller/note 메시지
- 4개의 판매자 질문 reply choice

- `매물로 돌아가기`

- 직접 확인 요청
- 출처 질문

시세 확인은 상대에게 보내는 메시지가 아니므로:

`내가 직접 비슷한 매물 찾아보기`

라는 별도 행동으로 분리한다.

`current_stage = "chat"`을 저장/복원할 수 있다.

기존 `chat_history`는 그대로 사용하므로 상세 → 채팅 → 다른 화면 → 다시 채팅으로 돌아와도 대화는 유지된다.

- 상세에 하나의 seller-chat CTA가 존재
- CTA를 누르면 current_stage가 chat으로 변경
- DetailPanel은 숨고 SellerChatPanel만 표시
- 질문 4개와 직접 검색 1개가 분리됨
- 채팅에서 뒤로가면 같은 상세로 복귀
- 누적 대화가 다시 열어도 유지
- 390×844에서 전용 채팅 화면이 가로 overflow하지 않음

으로 바꾼다.
